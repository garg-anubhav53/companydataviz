## Natural Language Query Extension — Coding Assistant Handoff

### Overview
Extend the existing routing and lookup architecture to support ranked and filtered
queries. Same pattern: LLM extracts intent, client resolves against CSV data. No
additional API calls. Below are some illustrative examples of natural language queries that should be supported, but they are not exhaustive, our LLM should be able to handle a variety of others at the same complexity level

---

### New JSON shape
Add to the routing system prompt alongside the existing `lookup` shape:
```json
{"chart": "query", "sort_by": "<field>", "order": "asc|desc", "limit": 3, "filter": {"field": "<field>", "contains": "<value>"}}
```
`filter` is optional. `limit` defaults to 3 if not specified.

**Example mappings to include in the system prompt:**
- "top 5 companies by ARR multiple" → `{"chart": "query", "sort_by": "arr_multiple", "order": "desc", "limit": 5}`
- "highest valuation companies with Sequoia" → `{"chart": "query", "sort_by": "valuation", "order": "desc", "limit": 3, "filter": {"field": "Top_Investors", "contains": "Sequoia"}}`

---

### Client-side — `resolveQuery(params, data)` in `main.js`
1. If `filter` present, reduce rows to those where `row[filter.field]` contains
   `filter.contains` (case-insensitive)
2. Compute `arr_multiple` on the fly as `val_billions / arr_billions` — exclude nulls
3. Sort by `params.sort_by`, take `params.limit` rows
4. Render as a simple formatted list in the chat — no canvas, no chart

---

### Supported `sort_by` values
`valuation`, `arr`, `arr_multiple`, `founded`, `employees`, `g2_rating`

---

### Verification
- Existing `lookup` path unchanged — test a simple lookup still works
- Null rows excluded before sort — no NaN values in output
- `arr_multiple` only computed where both ARR and Valuation are non-null
- Filter on `Top_Investors` uses `contains` not exact match — Sequoia appears as a
  substring in multi-investor strings
